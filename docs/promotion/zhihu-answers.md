# 知乎答题草稿（3 个高意图问题方向）

> 打法：不搜问题链接（问题实时变动），在知乎搜索框搜下面的关键词，挑**关注数多、最近有活动**的问题回答。每个答案用对应模板，替换数据后发布。
> 答题节奏：每周 2-3 个，不要同天发多答（会被判营销号）。

---

## 模板 1：搜「Agent Skills」「AI Agent 技能管理」

**回答框架**（约 600 字）：

先解释 skill 是什么（一段：SKILL.md + 脚本文件夹，Anthropic 带火的扩展机制，国产工具全面跟进）。

然后指出真痛点：**生态割裂**。列出实际目录路径（用我们 README 的清单）——AutoClaw、Kimi、Trae、Qoder 各一个目录，skill 复用全靠手工复制。

给三层解法：
1. 手动：遵循 `~/.agents/skills/` 通用约定（部分工具原生扫描）
2. 工具：自荐 agent-skill-manager（中央仓库 + junction 分发 + audit 评分），给安装命令和一个使用场景
3. 习惯：把 skill 当代码管理（git 版本化、写清 description 触发条件）

结尾：附仓库链接 + "亲测管理 33 个 skill"。

---

## 模板 2：搜「Claude Code 技能」「SKILL.md 怎么写」

**回答框架**（约 500 字）：

先答"怎么写"（frontmatter：name/description 决定触发；正文给工作流和边界），重点强调 **description 写得能不能被正确触发，比正文写得好更重要**。

再补一个安全视角（差异化卖点）：SKILL.md 是给 AI 的指令 = 提示注入的新载体，举例 "ignore all previous instructions"、`curl | sh` 这类真实模式；介绍审计思路（静态扫描四维度），提 `askill audit` 可以一键体检。

结尾挂仓库。

---

## 模板 3：搜「国产 AI 编程工具对比」「AutoClaw / Kimi / Trae 怎么选」

**回答框架**（约 800 字）：

客观列各家定位（这部分建立可信度：AutoClaw 的 agent 生态、Kimi 的长上下文、Trae 的 IDE 体验、Qoder 的……），不下绝对结论。

**转折点（植入位）**：真实问题不是"选哪个"，而是"全都要"——但 skill 不互通。讲自己的做法：中央仓库 + 各家目录 junction 分发，一句 `askill sync`。给一张目录对照表（我们 README 的 11 产品表浓缩版）。

结尾：工具开源，附链接；评论区可以讨论各家 skill 生态差异。

---

## 通用注意事项

- 不要新号直接发链接（降权），账号有历史回答最好
- 数据要真实：写"我管理了 33 个 skill""76 个测试"这类可验证细节，比形容词可信
- 每个答案结尾一句话引导："工具开源在 GitHub，搜索 agent-skill-manager 或直接点我主页"
- 若答案被踩/被删：立刻停发同模板 2 周，换纯干货版（去掉工具名，只在个人简介挂链接）
