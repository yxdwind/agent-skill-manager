# v0.15.0 功能规划：创作与发布闭环（Create & Publish Loop）

> 规划日期：2026-10-03　**状态：已实施（R1/R2/R3 全部落地，见 CHANGELOG v0.15.0）**　基线：v0.14.2（审计 14 项全部闭环，239 tests 全绿）
> 选型依据：消费侧（search/install/adopt/update/watch）在 v0.11-v0.14 已完备，**创作与发布是产品闭环里仅剩的空白环**；skills.sh 无发布 API、收录锚定 GitHub 仓库（实测核实），发布能力应建在已有的 verify/audit/sources 地基上，而非对接第三方。

## 目标

把 askill 从「技能消费工具」升级为「技能全生命周期工具」：

```
askill search → install → watch(改) → update(升)  ← 现有：消费闭环 ✅
askill new → verify/audit → publish              ← v0.15：创作发布闭环 🆕
```

---

## R1：`askill new <name>` — 技能脚手架

**价值**：60 秒起一个合规技能，frontmatter 天然满足全部目标产品要求。

**行为设计**：

- `askill new my-skill` 在中央仓库创建 `~/.agents/skills/my-skill/`，骨架：
  ```
  my-skill/
  ├── SKILL.md          # frontmatter 按目标产品要求生成 + 使用说明模板
  ├── references/       # 渐进披露：详情移入此目录（spec 的 500 行软限制）
  └── scripts/          # 可执行脚本目录（audit 会扫，模板里写明风险提示）
  ```
  `--minimal` 只生成 SKILL.md。
- **frontmatter 智能预填**（能力矩阵声明式体系的直接受益者）：
  - 默认填 `name`（校验小写连字符规则 + 与目录名一致）+ `description`
  - `--target qwenwork` 追加 `version` + `description_zh`（读 `products.py` 的 `required_frontmatter`，未来任何新产品声明了新字段，脚手架自动跟上，**零代码改动**）
  - `--target` 可多选；不指定时按全部声明了必需字段的产品生成超集
- 生成后**自动跑 verify**（复用 `check_spec` + `product_frontmatter_issues`），现场证明脚手架合规
- 名称冲突：目录已存在 → 报错并提示（与 install 的防覆盖语义一致）
- 成功后输出下一步提示：`askill sync`（分发）/ 直接编辑 SKILL.md

**验收**：new 出来的技能零修改通过 `askill verify`；--target 组合生成的字段与矩阵文档一致；名称非法（大写/连续连字符/超 64 字符）被前置拦截。

## R2：`askill publish` — 一键发布

**价值**：把「改完技能」到「别人能 `askill install owner/repo@skill`」之间的手工步骤压成一条命令。

**行为设计**：

- 发布单元：单个技能（`askill publish my-skill`），布局两种可选：
  - 单技能仓库：SKILL.md 在仓库根（装法 `askill install owner/repo`）
  - 多技能仓库：`<skill>/SKILL.md` 子目录（装法 `askill install owner/repo@skill`）
- **发布前门禁**（默认全开，逐项输出结果）：
  1. `verify` 全绿（agentskills.io 规范 + 按产品 frontmatter）
  2. `audit` 结论非 dangerous（risky 允许但高亮警告）
  3. 无未提交的变更（中央仓库若为 git 仓库）；非 git 目录先 `git init`
- **发布动作**：
  - `--repo owner/name`：推送到已存在的 GitHub 仓库（用现有 git/gh 凭据通道，含 SSH 443）
  - `--create`：gh CLI 创建新仓库后推送（无 gh 时输出手工指引退出）
  - 默认 `--dry-run`：只跑门禁 + 打印将执行的 git 动作，**实推必须显式 `--push`**
- 发布成功输出：可安装命令（`askill install owner/repo@skill`、`npx skills add owner/repo`）、skills.sh 收录说明（收录随 GitHub 仓库自动发生，排名随安装量增长，无 API 可调用——如实告知）
- 发布记录写入 sources 同款 bookkeeping（`.askill-published.json`：repo/branch/commit/时间），供后续 `publish` 增量更新与 `update` 反查

**验收**：dry-run 对不合规技能逐项给出可操作的失败原因；合规技能一键可装（发布后用 `askill install` 回装成功）；全程零第三方依赖（git + 可选 gh，均已在依赖面内）。

## R3：顺带小项（同版本捎带，各半天内）

1. `list --json` 补 frontmatter 字段展示（name/version/description_zh 缺失标记）——发布前自查的前置体验
2. `watch` 事件输出支持 `--json` 行流（每行一个事件对象）——脚本化消费者已在要求 JSON 契约的自然延伸
3. README「典型工作流」增加创作发布一段；`docs/product-matrix.md` 链接进 new 的 --target 帮助文本

## 非目标（本版明确不做）

- **双向同步**（产品目录 → central 自动回收）：冲突语义复杂，与 adopt 的手动语义重叠，留待 v0.16 单独立项
- **多机云同步**：git 原生能力已覆盖（中央仓库本身可 clone），避免重复造轮子
- **skills.sh 排名/统计对接**：对方无 API，遥测数据不可编程获取

## 里程碑

| 阶段 | 内容 | 验收门槛 |
|------|------|---------|
| P1 | R1 `askill new` + 测试 | new 产物零修改过 verify；矩阵字段联动有测试锁定 |

## 风险与对策

- **凭据依赖**：publish 需要 git 推送权限——本机已验证 SSH 443 通道可用；gh 缺失时降级为手工指引而非失败
- **误发布**：dry-run 默认 + 门禁阻断 + `--push` 显式确认，三道闸
- **模板僵化**：frontmatter 模板从 `products.py` 声明生成而非硬编码，产品要求演进时脚手架自动跟随
